### ② 进入 3 天实测前**必须**先做（否则 Day1 就会撞假故障）

| 动作 | 为什么 |
|------|--------|
| 1. `data\lawfirm.db` 备份到 Seafile 目录**之外** | 历史事故：Seafile 曾清空目录 |
| 2. 三台机器 `setx LAWFIRM_DB ""` 并重启 | 残留该环境变量会**静默**读错库，被误判为同步问题 |
| 3. 把库合并为单一文件（清掉 `-wal`/`-shm`） | WAL 伴生文件 + Seafile 同步时序 = 头号风险（打不开库 / 库损坏 / 读到旧数据） |
| 4. Seafile 忽略 `csharp/*/bin`、`csharp/*/obj` | 实际最大的冲突源（build churn），不是数据库问题 |
| 5. 三台各自导出到 **Seafile 之外**的目录 | 同名 `个人结算总表_张三.xlsx` 必冲突 |
